\section{跨论文的系统性比较与讨论}
\label{sec:synthesis}

六篇论文共同面对的问题，是如何把持续增长的历史转化为后续任务能够维护、找到并正确使用的记忆。但它们干预的环节不同：有的改变信息组织，有的改变访问范围，有的学习证据使用经验，还有的约束记忆操作的执行。本节据前述论文证据整理方法之间的联系，并把原文结果、解释性推演与课设选择分开；这些阅读判断不等同于已经完成的团队实验或逐项讨论记录。

\subsection{机制之间的联系：互补发生在什么条件下}

\textbf{组织结构与访问范围。} StructMem 强调同一事件内的事实与关系绑定，以及跨事件的综合；Semantic XPath 强调查询应落在哪个结构范围。二者可以用来区分“存储时丢失关系”和“读取时选错范围”这两类问题：即使存储正确，也可能检索错会话或错节点；即使检索范围正确，也可能因为原始抽取已遗漏关系而无法回答。这里的互补是分析思路，不能据此认定把 XPath 接到事件记忆上就一定有效；还需定义结构映射、证据来源与额外查询成本。

\textbf{取回证据与使用证据。} Hindsight 的 recall 与 reflect 分别涉及检索和利用记忆推理；MetaMem 则把可复用的知识利用经验作为优化对象。它们共同提示：检索命中后仍可能出现重复计数、时间关系误读或不当综合。分析回答错误时，需要区分“证据没有进入上下文”和“证据已进入但被用错”。改善前者的检索策略与改善后者的利用经验可能互补，但效果必须分别验证，不能只观察最终分数便认定瓶颈已经解决。

\textbf{更新策略与操作语义。} HyMEM 在具体任务中决定如何合并、替换和刷新经验；Text2Mem 则强调操作应具有明确的目标、参数与可检查的执行结果。前者帮助讨论“何时更新、保留什么”，后者帮助讨论“实际执行了什么、状态是否符合意图”。但二者的表示与接口并不天然一致，尤其不能把多模态连续记忆直接当作参考 SQL 后端的一条文本记录。

\textbf{事实、观点与利用经验。} Hindsight 对事实与观点的区分，以及 MetaMem 对知识利用经验的建模，说明记忆条目的角色需要明确。世界事实、对主体的推断、操作经验和回答策略不宜无差别地作为同一类证据。它们分别在什么条件下可用于回答、何时需要更新或撤销，是比较系统设计时应追问的问题，而非仅看数据结构叫“图”还是“树”。

\subsection{共同取舍：结构化获得了什么，又付出了什么}

\textbf{关联完整性与抽取误差。} 事件、实体关系和层级有助于保留上下文，但结构本身也由抽取或整理得到。实体合并错误、时间绑定错误及摘要遗漏会进入后续检索和推理。因此应同时检查结构是否找到了来源，以及来源中的关键事实是否仍被保留，不能用“有来源 ID”替代内容正确性。

\textbf{检索覆盖与上下文开销。} 多路召回、事件补齐和更大范围的结构访问可能增加有效证据，也会引入冗余和无关信息。评价局部改动时，应在相同回答上下文预算下观察证据覆盖、回答质量及成本，避免把“给模型更多文本”的收益全部归因于结构设计。

\textbf{动态适应与错误固化。} 综合记忆、观点更新和反思经验能够适应后续任务，也可能保留错误概括或过拟合开发样本。讨论应追溯更新依赖的证据和反馈，区分系统运行中自然获得的信息与离线优化时使用的标准答案；后者不能出现在独立测试的记忆构建或检索条件中。

\textbf{表达能力与验证范围。} 明确操作 schema 能减少歧义、支持执行检查，但可解析不代表目标选择正确，可执行也不代表执行后满足用户意图。同样，能组织复杂多模态经验，不代表在更简单的文本任务上具有成本优势。需要分别报告表示、访问、推理和执行各环节的约束。

以上是用于比较的分析维度，不是声称所有论文都已经验证了这些取舍的同方向收益。具体优缺点需回到各篇论文的实验、消融和局限，避免把设计动机当成已证明的结论。

\subsection{怎样比较实验结果，才支持方法判断}

论文内部的对照比跨论文总分更适合解释机制。例如，StructMem原文表2中，多跳分数由去掉跨事件综合时的66.31\%升至完整方法的68.77\%，而开放域两者均为46.88\%；证据支持综合模块在该设置下改善部分能力，不能扩展为每类问题都获益（PDF第4页）。MetaMem原文表2中，Qwen设置下完整方法、去掉反思、去掉演化分别为71.90\%、70.02\%、68.33\%，支持两个环节在其学习与测试条件下有作用，也不能忽略规则学习所用的答案反馈及调用预算（PDF第7页）。

收益与代价还可能同时出现。Semantic XPath的GPT-5 mini在LoCoMo上由全量上下文的74.55分降至65.19分，平均输入由24,857降至3,032 tokens（原文PDF第7页表1），体现的是特定配置的准确性与输入规模取舍。Text2Mem的GPT-5工作流ESR为100\%，EMR为11.90\%（原文PDF第8页表3），说明运行成功仍可能不满足大量状态要求；二者分母不同，不能用相减计算失败任务比例。Hindsight演示论文中的跨模型总体结果、HyMEM不同领域的更新分析，也应分别保留各自配置和证据边界。

比较时应记录任务与数据划分、模型角色、是否训练或使用优化反馈、检索范围和预算、评价指标、主要成本六类条件。原论文的跨系统结果说明其各自实验条件下的表现；要判断某个结构或机制的作用，优先看该论文内部控制变量的消融。若本组复现，则所有对照共用明确的数据划分和评价口径，并说明与原论文配置的差异。

成本也要按机制分开：写入与综合开销、检索和回答开销、优化与裁判开销不是同一项。无需训练基座模型，并不等于无需多次采样与反馈；一次构建的成本，也不能直接与一次查询的成本相比。

\subsection{共同案例：行程变更中的范围、状态与证据}

以下为自拟教学案例，不是论文原例或已运行的对照实验。设同一用户连续留下三条有来源时间的记录：$s_1$（10月20日）：“10月23日去A地”；$s_2$（10月21日）：“取消A地，改为10月24日去B地”；$s_3$（10月22日）：“10月24日先到B地，再去C地，仍按新计划”。问题是“当前计划哪天出行，经过哪些地点”。依据现有记录，应回答“10月24日，先B地后C地”，并引用$s_2,s_3$；不能把已取消的A地拼入当前路线，也不能把记录时间当作出行时间。

若用户接着说“暂时不要再提这次行程”，系统还需澄清或通过既定产品契约确定：是降低检索优先级、关闭主动提醒，还是删除记录。以Text2Mem为参照，Demote、Delete和Expire具有不同语义，不能任意互换；即使降低了权重，也不能单凭这个状态断言证明上层应用绝不会提醒。应检查选中的行程、改变的字段、作用期限及无关记录是否符合要求。这里的断言设计是阅读建议，不声称原文已经覆盖此完整场景。

本例将失败定位到四个可区分的位置：抽取时丢失取消信息，访问时只找到旧版本，回答时混合新旧路线，执行时误改其他行程。不同方法为这些问题提供不同工具。仅看到最终答案出错，无法决定应增加图关系、扩大检索范围、学习规则还是修改操作后端；还需查看对应的来源、上下文及状态变化。

\subsection{课设选择：以StructMem为主线，按错误类型借鉴其他机制}

本组既定课设方案以LoCoMo小子集上的StructMem方法复现为主，采用一个回答模型，设计原始对话Flat RAG、去掉跨事件综合的事件记忆和完整StructMem三组对照\footnote{范围依据仓库\texttt{docs/project-plan.md}，版本\texttt{1862df9}；此处说明比较设计，不表示三组实验已全部完成。}。选择依据首先是任务匹配：当前问题是长对话中人物、时间和跨事件信息的组织及问答。其次，事件记忆与综合记忆具有可分离的接口，能够围绕同一条主线解释各组件作用；这比同时实现六套任务、训练与评价条件不同的系统更适合现有课程范围。

其余工作提供的是具体的比较和诊断依据。Hindsight与Semantic XPath提示我们检查实体、时间及范围约束，并与合理的元数据过滤基线比较；MetaMem提示把“证据未取回”和“取回后用错”分开；HyMEM提示区分跨任务经验更新与当前工作上下文刷新；Text2Mem提示在操作记录中明确影响范围，并验证结果而非只记录调用成功。这些参照不要求当前项目新增多模态训练、完整图服务、元记忆优化流程或十二操作后端。

后续若根据错误案例尝试局部改动，应先固定数据划分、回答模型与评分方式，再针对改动控制检索或回答预算。例如，检验跨事件综合时只改变综合模块；检验范围约束时保持其余检索条件一致；检验证据利用时可固定提供的证据进行诊断，但不能把这种诊断结果当作完整检索系统成绩。开发集可用于分析和选择配置，独立测试答案不能参与记忆构建、检索或规则优化。

因此，本节形成的阅读判断是：\textbf{结构应服务于明确的错误位置，验证应覆盖对应的状态或证据链。}来源标识不替代内容核对，检索命中不替代推理正确，可执行操作不替代意图满足。机制组合在结构映射、反馈边界和成本上仍需单独验证；这里不预设其效果，也不将其登记为已经完成的创新实验。
