# B：S0 普通检索基线——10月22日课堂问答准备

负责人：`YaoYang-123456`。依据 B 的 [实际运行记录](s0-local-run-20261019.md)、F 的 [真实回答交接 PR #42](https://github.com/YaoYang-123456/NLP-2026-Team08-Structured-Memory/pull/42)、A 的固定输入及 [项目方案](../docs/project-plan.md)；2026-10-20 的备忘稿。回答仅限已执行的操作和可核对的条件，不冒充人工验收。

**1. B 做的是什么？**  
B 建立最朴素、可解释的系统基线：原始对话按消息分块，保留会话日期与说话人，固定 MiniLM 编码后按余弦相似度取每题最相关的60块。B 不做事件抽取、跨事件综合、答案生成或评分。

**2. 为什么不用 BM25 或自己做新的语言模型？**  
本组方案已冻结 S0 为向量检索，用固定 all-MiniLM-L6-v2（384维、归一化），不必训练新模型。旧 MetaMem 试点采用 BM25 和其他数据，不能冒充本项目 S0 的结果。

**3. 题目与数据如何保证公平？**  
A 固定三个开发会话、30道题（类别8/8/7/7），其中5题是30题的子集，使用原始 `(sample_id, qa_index)` 联合主键；不根据模型成绩换题，不把留出会话混入开发集。所有方法应使用同一清单。30题只是小规模开发试跑，不是正式留出集结论。

**4. 为什么说检索成功不能代表回答正确？**  
S0 真实检索30/30题、每题60块，只表明系统能按约定提供上下文；F 实际生成成功30/30条，只说明API返回有效回答。正确性需要 E 用冻结答案和裁判统一判定。截至本稿尚无准确率。

**5. 怎样追踪证据、避免标准答案泄漏？**  
每个块具有可回到 `sample_id/session_N/dia_id` 的 `source_ids`，正文保留时间、说话人和原话。B 的输入仅含 A 隔离出的会话与问题，不含 `answer`、`evidence` 等评分字段；F 校验严格 JSONL 白名单，E 才在回答后引入标签。

**6. 代表案例说明了什么？**  
`conv-42/15` 的问题是 Nate 何时染成紫发。检索排名1是2022年4月15日会话里的 “Dyed my hair last week”，排名2是该会话的紫发图片描述，排名3是一条相近却可能干扰的其他场景图片描述。F 给出“四月十五日前一周”的实际预测。它展示了时间证据与干扰同时被检索到，但**本例是否判对仍待 E**。

**7. S0 与完整 StructMem（S2）究竟不同在哪？**  
S0 直接检索原始对话块；S2 先抽取事实与关系、做时间绑定，再构建跨事件综合记忆，回答时使用事件条目与综合内容。S0 与 S2 是**整套系统对照**，不是控制其他因素不变的单一组件消融；S1（去掉综合）才用于研究综合模块本身的影响。S2 真实综合与答题尚未完成。

**8. 为什么不能说“严格复现原论文成绩”？**  
论文使用自己的数据/模型/嵌入条件，本组固定一种 DeepSeek 回答模型和本地 MiniLM，并且仅在30道开发题上试跑。模型、提示词、嵌入及规模差异必须说明；不能把论文原表数值与本组直接排名，也不能根据30题推断普遍优势。

**9. 到目前为止费用多少？**  
B 的检索在本机 CPU 上执行，不调用付费问答API。F 在同一题单按5＋25次调用，实际输入132,531 tokens、输出421 tokens，依据调用时高峰价格估算约0.26843元，账单尚未核对；E评分和D综合的费用不包含在这个数字里。
