| 处理 | 条数 | 判定依据 |
| --- | ---: | --- |
| 保留 | 136 | 前句补足了人物、对象、具体事件或时间参照。 |
| 删除 | 79 | 展示综合片段时已有父级时间标题，旧规则又带入了一条提供同一会话参照的句子。 |
| 删除 | 62 | 候选前句只是话题转折、概述或收尾，删去后当前事实仍清楚。 |
| 删除 | 22 | 原句已提供关键参照，或 `next` 一类词只表示先后顺序。 |
| 删除 | 9 | 旧边连到别的日期、话题或人物，前句缺少可用的参照。 |
| 换句 | 7 | 原句有具体依赖，同一综合的其他更早原句能补足。 |

旧规则仅因时间词加了 110 条边，其中建议删去 109 条。保留的一例是 Joanna 在 Nate 比赛期间旅行，前句写的是比赛日期 7 月 8 日，父级标题记录的是 7 月 10 日。另有 3 条同时命中时间词与句首指代，候选前句仍能补充人物或具体事件，建议保留。删除重复日期边的前提是当前渲染仍保留父级时间标题。[B 的渲染入口](https://github.com/YaoYang-123456/NLP-2026-Team08-Structured-Memory/blob/7126895/src/hybrid_retrieval.py)

## 正式接入前要对齐的地方

1. 先确认原句失去了什么信息，再补最短的完整前句。遇到有具体指向的 “This milestone”，找明确写出该事件的前句。若只是 “This exchange” 之类的概述，默认只保留选中的原句。
2. 先判断相对时间参照的是会话日期还是某个具体事件。渲染保留父级时间标题，正文沿用原来的时间表达。若前文写出了具体事件参照，再连到对应原句。
3. 复核否定、条件和句中代词时，检查被否定或被限定的具体对象。对仍有多个可能先行词的案例，交给成员结合父综合判断。
4. **对齐句位起点。** [C 首样 #83](https://github.com/YaoYang-123456/NLP-2026-Team08-Structured-Memory/pull/83) 的句位从 1 开始，D 的候选 ID 从 0 开始。接入时按父综合和原句文本核对后统一编号。例如同一个 “She shared a photo” 在 C 首样是第 4 句，在 D 包是位置 3。
