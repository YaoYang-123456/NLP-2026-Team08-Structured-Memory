# 30 题离线覆盖试点：混合检索、MMR 与互补证据选择

日期：2026-11-03。结论：**当前互补选择原型没有表现出超过 MMR 的独立覆盖收益，不进入主创新的扩大实验。** 保留混合检索和 MMR 作为简单对照，先完善公共实验条件和复现评价；互补原型及负结果保留供复查。

后续已单独验证并选择[多粒度证据打包方向](phase2-anchor-pilot-20261103.md)。它改变事件/综合的上下文范围和预算分配，与本报告只改变事件选择的 C-v1 不同；本报告的配置、数据和负结果不变。

本轮已执行 30 题 × 3 种选择器，共 90 份上下文，并完成一次确定性复跑。回答调用、裁判调用、留出题使用均为 0。覆盖评价由 Codex 辅助逐项核查，尚未经组员本人复核；没有新答案正确率结果，没有改原始标签或历史评分。

## 1. 固定条件与实现

- 数据：原开发 `conv-48/42/41` 的同一 30 题，完整 3,712 条事件及原生向量。三个 SQLite 副本逐字节与此前校验过的 C 交接包一致。
- 查询编码：固定 `all-MiniLM-L6-v2@1110a243fdf4706b3f48f1d95db1a4f5529b4d41`，CPU、384 维、归一化、256 长度上限。仅补齐模型及计数器静态文件；试点执行使用本地缓存，禁止 Hugging Face 在线加载，不向回答模型发送数据。
- 每题候选：本会话全事件库的向量 top-120 与 BM25 top-120 的并集；词法分数大于 0 才进入词法列表。BM25 使用 Porter 词干、固定停用词、`k1=1.2,b=0.75`。两路等权 RRF，`k=60`，按最高 RRF 分数归一化。实际每题 159–223 条候选，三组完全相同。
- 综合：只取得 69 条实际调用过的综合正文，缺少完整 91 条综合导出。因此固定每题原 S2 的 5 条综合，三组逐字一致，不重新检索这个不完整的综合库。本轮只比较事件选择。
- 预算：每题最多 **4,096 个 `cl100k_base` 代理 tokens**，包含 5 条综合、短证据编号、说话人、记录时间和完整事件正文。固定综合先占 1,955–2,524 个代理 tokens（含短编号及分隔符），剩余预算按完整事件填充；放不下就跳过，不截断正文。实际选择 32–48 条事件。代理计数不等于 DeepSeek 计费 tokens，也不是含问题与指令的完整请求预算。
- 长来源 ID 只留在 trace；三组使用相同简洁展示。候选顺序决定短编号，避免选择顺序影响编号长度。问题类别、参考答案、reference evidence 不参与选择。

[冻结配置](../configs/phase2-coverage-pilot.json)和[执行脚本](../scripts/offline_coverage_pilot.py)先于第一轮选择确定。只运行一个参数配置，复跑仅验证确定性，不做网格搜索，也没有根据结果调参。

令 `r` 为归一化 RRF 相关性，`d` 为与已选事件的最大非负余弦相似度：

| 选择器 | 贪心选择得分 |
| --- | --- |
| 普通混合检索 H | `r` |
| MMR M | `0.70 r - 0.30 d` |
| 互补选择 C | `0.55 r + 0.20 f + 0.25 g - 0.30 d` |

`f` 是问题特征的边际覆盖：词干、明确说话人姓名、显式日期、时间问句的正文时间表达，权重分别为 1/2/3/1；每个特征按 `1/(1+已覆盖次数)` 衰减，再除以特征总权重。显式日期只软匹配记录日期，不宣称记录日期就是事件发生日期。`g` 为原消息来源组的最大相关性，除以 `1+该组已选条数`；同源事实仍可多选，不将整个 session 合并。三组使用同一预算可行性检查和确定性 ID 排序。

这个原型检验的是一组明确的轻量规则。结果不代表所有可能的互补检索算法都无效；也不能因为包含问题特征和来源分组，就把它称为已成立的创新。

## 2. 正文支持评价

对 30 题建立 51 个支持检查项，每项记录可以支持它的实际事件/综合片段，允许替代证据，也允许必须同时出现的多条证据。程序逐项核对实际输入中的 ID **及原文子串**，不是只统计 source_id 命中。事件时间字段随正文绑定；相同词语对应不同人物、礼物赠予方向、不同来访日期等误命中均排除。

其中 25 题的 44 项用于检查答案相关支持；另外 5 题的 7 项仅检查可观察上下文：`conv-41/41`、`conv-41/45`、`conv-42/61`、`conv-48/23` 是上轮参考/推断边界案例，`conv-42/4` 的过敏限制可核查，但具体推荐答案还需要额外推断。五题仍执行全部选择并报告，**原问答评价分母仍为 30**，没有通过排除它们重算正确率。日期换算、跨会话指代等题即使清单齐全，仍需要推理。

完整注记、参考标签及原文只存于忽略的 `output/phase2-coverage-pilot-20261103/`。公共[统计 JSON](phase2-coverage-pilot-20261103.json)记录逐题计数、配置、版本、输入/注记哈希和核验结果。

| 指标 | 普通混合 H | MMR M | 互补 C |
| --- | ---: | ---: | ---: |
| 全 30 题支持检查项覆盖 | 45/51 | 48/51 | 48/51 |
| 答案相关支持项覆盖 | 38/44 | 41/44 | 41/44 |
| 25 题中支持清单完整 | 22/25 | 23/25 | 23/25 |
| 5 道边界题上下文清单完整 | 5/5 | 5/5 | 5/5 |
| 原先 4 个检索缺口补回缺失支持 | 2/4 | 2/4 | 2/4 |

按题配对：C 对 M **0 胜、0 负、30 平**；C 对 H、M 对 H 均为 **1 胜、0 负、29 平**。唯一完整覆盖差异是 `conv-42/55`：MMR 与互补选择都带入了普通混合遗漏的一条多项证据，一条事件承载三个支持项。因此“增加 3 项”不是三道独立改进，更不是三个新答对案例。

## 3. 缺口定位与保留风险

| 案例 | 三组实际观察 | 含义 |
| --- | --- | --- |
| `conv-42/57` | 都选到正确来访日期及对应活动证据 | 普通混合已足以补回；原来的另一次来访综合仍在，不能据此认定答案已修复 |
| `conv-48/173` | 都选到所问日期对应的课程条目 | 互补日期规则没有产生独占覆盖收益 |
| `conv-48/86` | 原先缺少的礼物证据未进入共同候选池；另一份原先已覆盖礼物的明确赠予证据在融合第 67 位，三组都没选中 | 前者是候选召回问题，后者是预算选择损失；仅有花束照片不能证明收到礼物 |
| `conv-41/49` | 跨会话桥接条目进入候选（融合第 76 位），但三组都未选入 | 需要识别具体事件之间的指代联系；一般相关性或来源分散不足以保留它 |

忽略预算、拿到全部共同候选与固定综合时，已核查清单的覆盖上界是 **50/51**。实际 M/C 为 48/51，差的两项在候选内；另有一项连共同候选都未覆盖。这个上界使用评价注记进行事后定位，**不是可部署选择器，也不是同预算 oracle**。

原历史 S2 在同一清单上为 47/51；新 M/C 补回两项但丢了一项原有礼物支持，净增一项。旧 S2 没有本轮预算限制，不能作为公平的算法优劣对照。原答对 19 题虽然均保留支持，其他题的已有局部支持仍可能受损。

进一步仅从既有选择结果中移除综合进行诊断，不重选、不补满预算：H/M/C 的事件支持为 **41/51、44/51、43/51**。C 相对 M 少保留 `conv-41/36` 的一项音乐活动证据，由共同综合补足。此诊断不是正式 S1 回答实验，也不支持 C 在事件层更优。

按题累计的不同消息来源数为 H 1,041、M 1,043、C 1,094；同来源额外条目数为 212/198/146；事件对余弦相似度 ≥0.85 的数量为 201/157/152。**来源更分散没有转化为更高支持覆盖**。这些是来源重复和向量相似度的代理指标，不能冒充语义冗余率、噪声率或答案质量。

## 4. 决定及下一步

预先约定的“两处旧缺口补回”由三组共同满足，但 C 没有通过“优于 MMR”的独立价值要求，事件层还出现退步。因此停止扩大 C-v1，不运行其付费回答批次或两个消融来寻找漂亮结果，不直接推进留出构建。

下一阶段保留 H/M 对照，处理共同的格式、预算、来源展示和评分绑定，再检验实际回答效果。若还要寻找方法创新，应先验证更具体的“事件之间的指代/关系连接是否能稳定补回缺失项”，把候选未召回和候选被挤掉分开。该问题目前只是待验证假设；不能围绕上述两题写特例，也不把 MMR 包装为新算法。六人的交付、依赖和继续条件已更新到[阶段规划](../docs/plans/2026-11-03-phase2.md)。

## 5. 复跑与验证

运行环境：Python 3.11；`torch 2.8.0+cpu`、`sentence-transformers 5.1.1`、`transformers 4.57.0`、`numpy 2.2.6`、`nltk 3.9.2`、`tiktoken 0.12.0`。首次补齐模型与计数器静态缓存，正式选择只读本地缓存。

这是离线研究原型的实际环境，与项目 `requirements-locomo.txt` 的版本不同。需要精确复跑时，在单独 Python 3.11 虚拟环境安装上述版本，不覆盖已有 CPU/CUDA 环境；本轮不修改项目公共依赖。模型使用配置中的固定 revision，准备好模型及 `cl100k_base` 静态缓存后再执行选择；脚本设置离线模式，不会用在线模型补缺。

新检出的仓库还需要按[数据说明](../docs/locomo-data-environment.md)准备同哈希 LoCoMo 源数据和原 30 题输入，并按 [C 完整交接说明](../docs/structmem-complete-handoff.md)取得已登记的事件数据库包，再执行核查脚本。下列路径是本次运行布局，可通过参数替换，输出目录必须是新目录。选择不需要评分标签；复算 51 项覆盖则需要向本轮整理人 `hycx233` 获取含标签的本地 `support-units.json`，核对公共统计 JSON 中的哈希，由 E 复核后继续受控保存，不公开入库。
