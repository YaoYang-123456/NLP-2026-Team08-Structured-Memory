# 30 题离线覆盖试点：混合检索、MMR 与互补证据选择

日期：2026-11-03。

**核心结论**：我们尝试的“互补证据选择（C-v1）”原型在 30 道开发题上**没有超过普通 MMR**，因此停止扩大 C-v1，保留这份负结果作为决策依据，并保留混合检索和 MMR 作为阶段二的基础对照。

> 后续我们转向了改变“事件/综合展示粒度与统一预算”的[多粒度证据打包方向](phase2-anchor-pilot-20261103.md)；本报告记录的是更早一轮“固定 5 条综合、仅改进事件排序”的离线试点。覆盖标注由 Codex 辅助逐项核对，待组员人工复核。

## 1. 实验设置与三种选择器

本轮跑了 30 题 × 3 种选择器（共 90 份上下文）并复跑一次验证确定性，全程离线（无 LLM 回答或裁判调用）：

- **数据与事件库**：冻结开发集 `conv-48 / 42 / 41` 的 30 道题，完整 3,712 条事件及原生向量（SQLite 副本与 C 交接包逐字节一致）。
- **查询编码**：固定 `all-MiniLM-L6-v2@1110a243fdf4706b3f48f1d95db1a4f5529b4d41`（CPU、384 维归一化、上限 256 tokens），仅读本地缓存。
- **共同候选池**：每题取本会话全事件库的向量 top-120 与 BM25 top-120（仅保留词法分 > 0 的条目，Porter 词干 + 固定停用词，`k1=1.2, b=0.75`）的并集，两路等权 RRF（`k=60`，按最高分归一化）。实际每题 159–223 条候选，三组完全相同。
- **综合部分**：因缺少完整 91 条原生综合导出，手头只有 69 条曾被检索过的综合正文，故本轮固定每题原 S2 的 5 条综合不变，只比较事件选择策略。
- **统一预算**：每题上限 **4,096 tokens**（`cl100k_base` 代理计数，含 5 条综合、短编号、说话人、记录时间和事件正文；不含系统指令和问题）。固定 5 条综合先占掉 1,955–2,524 tokens，剩余预算按完整事件填充，放不下跳过、不截断，实际选出 32–48 条事件。长来源 ID 留在 trace，不进入展示文本；题型和标准答案不参与选择。

[配置](../configs/phase2-coverage-pilot.json)和[脚本](../scripts/offline_coverage_pilot.py)在首次运行前冻结，只跑了一组参数，未做网格搜索。令 `r` 为归一化 RRF 相关性，`d` 为与已选事件的最大非负余弦相似度：

| 选择器 | 贪心打分公式 |
| --- | --- |
| 普通混合检索 **H** | `r` |
| **MMR（M）** | `0.70 r - 0.30 d` |
| 互补选择 **C** | `0.55 r + 0.20 f + 0.25 g - 0.30 d` |

其中 `f` 是问题特征的边际覆盖（词干、明确说话人、显式日期、时间问句中的时间表达，权重依次为 1 / 2 / 3 / 1，按 `1/(1+已覆盖次数)` 衰减并归一化；显式日期仅软匹配记录日期）；`g` 是原消息来源组的最大相关性除以 `1 + 该组已选条数`（鼓励覆盖不同来源消息，但允许同源多选）。

## 2. 支持证据覆盖结果

针对 30 道题建立了 **51 个支持检查项**，程序逐项校验实际选出的上下文里是否同时包含对应 ID 和**原文子串**（排除同名不同人、送礼方向相反或日期张冠李戴的误命中）。其中 25 题 / 44 项检查答案所需支持；另 5 题 / 7 项（`conv-41/41`、`conv-41/45`、`conv-42/61`、`conv-48/23`、`conv-42/4`）属于参考或推断边界案例，只检查可观察上下文，问答总分母始终保持 30。完整标注留在本地忽略目录 `output/phase2-coverage-pilot-20261103/`，公开统计见 [phase2-coverage-pilot-20261103.json](phase2-coverage-pilot-20261103.json)。

| 指标 | 普通混合 H | MMR（M） | 互补选择 C |
| --- | ---: | ---: | ---: |
| 全部 30 题支持项覆盖 | 45/51 | 48/51 | 48/51 |
| 答案相关支持项覆盖 | 38/44 | 41/44 | 41/44 |
| 25 题中支持清单完整 | 22/25 | 23/25 | 23/25 |
| 5 道边界题上下文清单完整 | 5/5 | 5/5 | 5/5 |
| 原先 4 个检索缺口补回情况 | 2/4 | 2/4 | 2/4 |
| 原答对 19 题支持保留 | 19/19 | 19/19 | 19/19 |
| 平均上下文 tokens | 4,083.93 | 4,080.43 | 4,079.07 |

按题配对比较：
- **C vs M**：**0 胜、0 负、30 平**，完全没有超过 MMR；
- **M vs H / C vs H**：均为 **1 胜、0 负、29 平**，唯一差别在 `conv-42/55`（MMR 和 C 多带入了一条包含 3 个支持项的事件）。

## 3. 原 4 个检索缺口复盘与风险观察

| 案例 | 三组实际表现 | 原因分析 |
| --- | --- | --- |
| `conv-42/57` | 三组都选到了正确来访日期与活动证据 | 普通混合检索已经能补回（但另一次来访的综合仍在，是否真能答对仍待实测） |
| `conv-48/173` | 三组都选到了对应日期的课程记录 | 互补日期规则没有带来额外独占收益 |
| `conv-48/86` | 一份缺失礼物未进入共同候选池；另一份原已覆盖的明确赠予证据排在融合第 67 位，三组都没选进预算 | 前者是候选召回问题，后者是被预算挤掉（只有花束照片不足以证明收到礼物） |
| `conv-41/49` | 跨会话桥接条目排在融合第 76 位，三组都没选进预算 | 单纯靠相关性或来源分散保不住这种跨会话桥接句 |

如果不限预算、把所有共同候选和固定综合全拿进来，当前候选池在 51 项上的覆盖上界是 **50/51**（唯一漏掉的一项没进候选池）。对比阶段一历史 S2（无预算限制，47/51），新 M/C 虽然净增 1 项，但在 `conv-48/86` 反而丢了一项原有礼物支持，说明预算挤占确实会导致局部损失。

此外，如果从现有结果里直接去掉 5 条综合（仅看事件本身覆盖），H / M / C 分别为 **41/51、44/51、43/51**——C 在 `conv-41/36` 上还比 M 少留了一条音乐活动证据。同时，C 确实让不同消息来源总数更多（H 1,041 / M 1,043 / C 1,094），同来源重复条数更少（212 / 198 / 146），高相似事件对（cos ≥ 0.85）略减（201 / 157 / 152），但**来源更分散并没有带来更高的支持覆盖**。

## 4. 决策结论

互补选择 C-v1 没有证明自己比普通 MMR 更好，事件层反而略有退步。因此果断停掉 C-v1，不拿它去跑付费回答或凑消融；保留 H / M 作为基础对照，转向更直接解决“综合太占预算”的[多粒度证据打包方向](phase2-anchor-pilot-20261103.md)（完整规划见[阶段二规划](../docs/plans/2026-11-03-phase2.md)）。

## 5. 复跑与验证

**原型运行环境**（独立 Python 3.11 虚拟环境，不要覆盖项目原有的 CUDA 环境）：
`torch 2.8.0+cpu`、`sentence-transformers 5.1.1`、`transformers 4.57.0`、`numpy 2.2.6`、`nltk 3.9.2`、`tiktoken 0.12.0`。

**数据准备**：先按[数据说明](../docs/locomo-data-environment.md)准备好同哈希 LoCoMo 源数据与 30 题输入，按 [C 交接说明](../docs/structmem-complete-handoff.md)准备好事件包，并用[核查脚本](../scripts/audit_development_memory.py)生成只读 SQLite 副本（`--events` 参数）。模型和 `cl100k_base` 首次备好缓存后，脚本全程离线运行。

复跑选择不需要标准答案；若需复算 51 项支持覆盖，向 `hycx233` 获取同哈希的本地 `support-units.json`（含标注，不入 Git）：

```bash
python scripts/offline_coverage_pilot.py select \
  --questions tmp/s0-integration-20261019/data/locomo/development.inputs.json \
  --events output/phase2-audit-20261103/final-review \
  --model-cache data/model-cache --tokenizer-cache data/tokenizer-cache \
  --out output/phase2-coverage-pilot-20261103/new-run

python scripts/offline_coverage_pilot.py evaluate \
  --selections output/phase2-coverage-pilot-20261103/new-run/selections.json \
  --annotations output/phase2-coverage-pilot-20261103/support-units.json \
  --out output/phase2-coverage-pilot-20261103/new-coverage.json
```
