# 开发集信息失真核查与方向判断

日期：2026-11-03。范围：已有开发数据与历史运行，新增模型请求 0。核查由 Codex 完成，不计作成员本人验收；没有重新生成回答、改写标签或修改历史评分。

这是方向探索的第一步记录。其后[互补选择试点](phase2-coverage-pilot-20261103.md)未观察到超过 MMR 的独立覆盖收益，最终已转向[多粒度证据打包](phase2-anchor-pilot-20261103.md)。下文保留当时的诊断与候选建议，当前实施以[阶段规划](../docs/plans/2026-11-03-phase2.md)为准。

## 结论

**当前证据不支持将“记忆失真驱动的自适应原文回溯”选为主创新。** 能找到局部过度概括和无依据补充，但本次发现的具体异常事件没有进入 30 题回答输入；在 11 道 S2 判错题中，没有找到明确与错答对应的答案相关记忆失真。

更直接的瓶颈是：4 题的关键支持信息已存在于完整事件库，却未进入实际回答上下文；3 题已有关键证据却未被回答正确使用；另外 4 题涉及参考证据的可见性或推断尺度。以上是根据来源与实际输入作出的诊断，不是通过重新生成得到的因果结论。

建议先统一回答格式、补齐基线与消融，将研究候选改为**问题约束引导的互补证据选择**，与普通混合检索和 MMR 去冗余作比较。只有超出简单方法的收益才继续作为方法贡献。详细分工见[更新规划](../docs/plans/2026-11-03-phase2.md)。

按当前观察，11 题分为 **4 题检索缺口、3 题证据利用、4 题参考/推断边界**。每题可能有多个影响因素，表中给出最直接的诊断路径，不声称完成了唯一根因的因果归属。

这 4 题参考/推断边界仍保留原来的 no 和总分母；不是宣布数据集标签错误，也不是把它们排除后重新计算更高准确率。当前 S2 仍为 19/30；S0 原始 16/30、既有日期裁定后 15/30。

### 已有回答指令的混杂因素

`configs/qa-structmem-20261020.json` 对 S1/S2 追加了通常不超过六词的要求，S0 没有这一要求。它是软限制，不保证每次严格执行，也不能单凭相关性证明其造成了漏答；但对多项列举题明显需要先做控制实验。

另外，按最近记录处理冲突的指令不能替代事件匹配：两次不同目的的来访不应仅因日期较新就相互覆盖。`conv-42/57` 中错误预测对应的较新来访本身在原文中成立，不能为了维护“失真”假设将其标作摘要幻觉。

## 4. 旧回溯方案是否足以解决问题

对 4 个检索缺口，以人工已知的缺失支持事实作**离线候选可达性检查**：从本题全部来源 ID 出发，包括综合 seed 关联这一更宽松的上界，再扩展同 session 前后各一条原消息。

- `conv-48/173` 的缺失来源可进入这一宽松候选池。
- `conv-42/57` 的日期话轮距离已命中的相关来源为两条，前后各一条仍够不到。
- `conv-48/86` 和 `conv-41/49` 的缺失支持来源也不在该局部候选池中。

因此，旧方案在这 4 题中**最多只有 1 题的关键来源进入宽松候选池**；还没有经过排序、预算选择或重新回答，不能说已经修好 1 题。原方案仅使用 covered 关联、排除 seed-only 关联时可能更少，目前缺原生综合导出，不能把这个上界当作实际命中率。

这直接否定了“主要靠命中来源附近回看就能覆盖当前主要错题”的预期。缺失信息有时在未命中的另一条来源或另一会话中，需要全库的互补检索。

## 5. 据此调整的实施决策

1. **暂不实施失真检测器、风险门控或逐题原文回溯主线。** 本次找到的失真例子作为质量案例保留；没有足够答案影响证据支持为全库增加一轮检测调用。
2. **先排除公共条件干扰。** 使用同一批上下文、同一时期模型，仅改变六词软限制，核查列举完整性；简洁来源展示另作工程优化，并对各组一致应用。
3. **用一次有限试点检验检索改进。** 候选为问题约束引导的互补证据选择，关注显式实体/日期、不同事件的目的，以及多个来源的互补性；候选搜索不能局限在原 top-60 命中来源。必须对比简单混合检索与 MMR，不将这些已有技术本身称为本组创新。
4. **先离线覆盖，后回答效果。** 在全部开发 30 题检查证据选入与噪声变化，再做配对回答。开发阈值只用于停止/继续判断，不证明泛化；配置锁定后才开展留出评价。

如果普通混合检索已经解决主要缺口，采用它作为工程改进，保留来源分组候选的消融结果；不为保住“创新”名目继续叠加机制。报告的研究价值可以来自可复算的瓶颈定位、质量成本对照及明确的负结果。

## 6. 复核方式与交付边界

使用[离线材料准备脚本](../scripts/audit_development_memory.py)，传入冻结官方原始 JSON 和 C 原始交接包，输出到一个新的本地目录：

```sh
python3 scripts/audit_development_memory.py \
  --source /path/to/locomo10.json \
  --event-archive /path/to/complete-handoff-20261019.zip \
  --out output/phase2-memory-review-new
```

脚本核对固定哈希、只读解析数据库、验证裁判绑定并重新产生相同抽样和逐题材料，不调用模型，也不会自动作出语义判断。它只接受该交接格式中的 PointStruct 数据对象，不需要安装 Qdrant。核查 JSON 中的语义判断仍需成员对照原文复核。

本次已实际运行该脚本并重新核对抽样、统计和题集；本地保存完整材料，公开路径只保存汇总和不含标准答案的核查注记。尚未执行回答格式对照、新检索算法、留出实验或成员人工验收；不将这些计划写成已完成。
