## 后续冻结与独立测试计划（本轮不执行）

当前十题已参与方法设计，不再把它们命名为独立验证集来证明泛化。现有测试接口存在，也不代表本轮新提示词与外部质量复核协议已具备完整测试交付条件。

1. 先解决评分政策中会影响解释的边界：明确衣物件数口径、观鸟参照时间异常的处理；若保留原参考，预先写明如何报告异常和敏感性分析。由人确认的结论另存，不将AI意见回填成人工标签。
2. 在查看测试内容之前保存一份正式冻结清单：代码提交、模型摘要/量化、Ollama版本与8192上下文、生成参数/输出上限/seed政策、数据清单哈希、BM25配置与事实格式、回答提示词全文及哈希、规则文件及来源、是否采用候选。组别、题目顺序、重复次数和总请求预算一并固定。
3. 冻结正确性v2与独立质量指标、评审输入、配置隐藏方式、评审者身份、一次复核范围、分歧转uncertain政策；不要在看到测试得分后扩大或缩小口径。记录人工验收仍为空或已取得的真实状态。
4. 候选选择只用允许的开发数据，预先规定完整有效覆盖门槛、并列处理和无候选满足条件时的退出方式。历史本地规则为完整覆盖且并列取最早版本，不能事后改成“偏向更复杂”。规则候选与人工回答提示词是不同变量，必须在正式计划中区分，不自动继承为同一种选择对象。
5. 用训练题或合成夹具核对最终冻结入口的答案隔离、输入绑定、恢复计数、一次性导出、失败/uncertain不作No；模型请求与APP评审成本分别统计。核对之后再由负责人决定是否正式打开独立测试，不能据本页称“测试已准备就绪”。
6. 获授权后只按冻结方案运行测试，输出覆盖、Y/N/U、失败与配对结果。测试结果不能反馈修改提示词、规则或检索后再冒充同一次测试；如发现基础实现错误，保留受影响结果、统一标注失效并说明新的评估边界。
