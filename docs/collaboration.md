# 小组协作与文件约定

## 1. issue 与分工

- **公开仓库注意隐私**：本仓库公开可见，issue、PR、提交信息和公开文档统一使用 GitHub 用户名，不填真实姓名、学号等个人信息。
- **按可验收单元建 issue**：一项能独立验收的工作建一个 issue（如一个模块实现、一组实验或报告的一章），指定一位主负责人，写清目标、产出路径和验收条件。小错别字等顺手改动不必单建 issue。
- **写作清晰易读**：issue 和 PR 说明尽量简洁直观，先写目标或结论，再列关键细节和下一步；避免大段难读的机器套话。
- **沟通同步**：微信群用来快速讨论和传大文件，涉及分工、接口或范围调整的结论顺手同步到对应 issue，方便大家查阅。只在有进展、遇到阻塞或完成时更新，不用频繁打卡。

## 2. 分支与 PR

1. 从最新 `main` 切任务分支，命名格式 `<用户名>/<issue编号>-<简短主题>`（如 `hycx233/75-qa-budget`）。
2. 只提交本任务相关改动，提交信息用 `feat:`、`fix:`、`docs:`、`chore:` 前缀写明做了什么。
3. 完成后向 `main` 提 PR：
   - 完成任务并准备结项时用 `Closes #编号`；
   - 仅同步阶段进展、登记计划或分批交付时用 `Refs #编号`，避免过早关掉还在做的 issue；
   - 还没做完但想提前对齐接口时，可以先开 Draft PR。
4. PR 正文简明交代改了什么、跑了哪些验证、还有什么待确认问题；没跑过的检查如实说明。

## 3. 审核原则（别互相过度打扰）

- **独立任务自查自合**：个人笔记、文档润色、任务登记和不影响他人的小改动，作者自查 diff、路径、链接和基本测试后直接合并，不用等别人批准。
- **公共改动定点请审**：涉及公共接口、共享数据格式、新增依赖、别人正在改的模块或小组最终材料时，在 PR 右侧 Reviewers 里**直接指定一位最相关的成员**，并在正文写明请对方重点看哪几件事。
- **不默认全组审**：不要把所有人都拉进 reviewer；审过之后的同范围小修补充说明即可，出现新的实质变化再请复核。
- 若仓库后续开了分支保护或遇到合并权限问题，在对应 issue / PR 说明即可，不私自改配置绕过。

## 4. 文件、目录与格式

- **命名**：新建文件和目录优先用简短英文、小写加连字符；老师原始文件和 6 篇论文 PDF 保留原名原文。
- **目录归位**：
  - 个人阅读笔记放 `notes/`（如 `notes/01-structmem-<用户名>.md`）；
  - 公共方案与接口放 `docs/`；
  - 代码、脚本、测试放 `src/`、`scripts/`、`tests/`；
  - 报告和小型交接包放 `reports/`，需要区分版本时加 `YYYY-MM-DD`；
  - 原始数据、模型缓存、运行输出和临时文件放 `data/`、`output/`、`tmp/`，均不提交 Git。
- **文本规范**：统一 UTF-8、LF 换行、文件末尾留换行，缩进遵守 `.editorconfig`（默认 4 空格，YAML / JSON 为 2 空格）。Markdown 尽量使用清晰标题、短段落和相对路径链接。
- **数据与密钥安全**：不提交 `.env`、API Key、原始数据集和带标准答案的完整标注；需要共享配置示例时提供不含密钥的 `*.example.*` 文件。
- **论文与实验记录**：引用论文注明页码或图表编号；明确区分论文原结果、本组实测结果和推测，不把 mock 或未完成实验写成实测结论。
- **平时作业文件说明**：11 月 1 日的平时作业已提交归档（见 [archive-20261101.md](../reports/homework/archive-20261101.md)），共享 LaTeX 报告和 Beamer 模板保留在 `reports/homework/` 供查阅和后续复用。

## 5. 大文件传输（20 MB 分界）

- **小于 20 MB**：不含密钥、标准答案或个人信息的必要交接包和最终文件，可直接放入仓库合适目录（如 `reports/artifacts/`），并在说明中附上文件大小、SHA-256、包内清单和读取方式。完整数据库、原始数据集和运行缓存仍留本地。
- **达到 20 MB（20,000,000 字节）**：包括视频、大型 PPT、模型权重、大压缩包等，统一发到小组微信群（**“请将该文件发送到小组微信群”**），不提交到 Git、PR 附件或另接网盘。仓库里只记录文件名、大小、用途、发送人和发送日期（方便计算时附 SHA-256），队友下载后放到本地 `data/` 或 `output/` 对应目录即可。
