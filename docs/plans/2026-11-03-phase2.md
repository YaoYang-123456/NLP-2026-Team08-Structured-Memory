# 阶段二规划：预算约束下的多粒度证据打包

更新日期：2026-11-03 · 总览入口：[阶段二总览 #69](https://github.com/YaoYang-123456/NLP-2026-Team08-Structured-Memory/issues/69) · 六人任务：`#70`–`#75`。

阶段二主方向已确定，全组围绕这一条主线推进，不再同时铺开多个方向。

## 1. 核心思路与创新定位

建议题目：**面向长对话问答的结构化记忆复现与改进——预算约束下的多粒度证据打包**。

**要解决什么问题**：阶段一复现的 StructMem 在回答阶段会固定拼入 `top-60 事件 + top-5 完整综合`。我们把上下文统一压到 4,096 token 后发现，光 5 条完整综合就平均吃掉约一半预算，里面夹杂了不少和当前问题无关的句子，把真正需要的事件细节挤了出去。

**我们的做法**：把“按什么粒度检索”和“给模型看什么范围的上下文”分开：

1. 把跨事件综合拆成完整句子，和完整事件放进同一个候选池一起打分排序；
2. 统一在 **4,096 token** 证据预算里挑选事件和综合片段，不再强制先塞满 5 条整段综合；
3. 如果选中的综合句带有悬空的代词（如句首 `She`）或相对时间表达，就把它在原综合里的相关前文打成一个整体包一起塞进去，避免断章取义。

**课程级定位**：这是一个清晰的组合式改进——以 StructMem 双层记忆为底座，借鉴 Semantic XPath 的结构范围选择和 RECOMP 的抽取式压缩思想，复用混合检索与 MMR。我们的核心工作是面向 StructMem 双层记忆的**统一预算分配 + 上下文依赖成组打包 + 同条件消融与成本分析**（不夸大成首创分层检索或通用指代消解）。详细文献关系和可直接汇报给老师的表述见[方向决定](../../notes/phase2-direction-decision-20261103.md)。

**已排除的方向**：前期核查表明，记忆失真检测、原文邻近回溯、互补来源分散（C-v1）在现有数据上都没有明显收益，再加上新知识图谱、MetaMem 在线训练等开销过大，均不再投入，相关负结果保留在报告中说明决策依据。

**默认实验口径**：

- **证据预算**：默认 4,096 token（用 `cl100k_base` 统一计证据文本长度；实际花多少钱以 DeepSeek API 返回的 `usage` 为准）。2,048 档仅按需要补充。
- **数据与基线**：沿用阶段一冻结的 30 道开发题与 51 项支持标注（其中 25 题 / 44 项检查答案支持，5 题 / 7 项检查参考/推断边界上下文，问答总分母始终为 30）。阶段一的 S0（15/30）和 S2（19/30）保持原样作为历史基线，不和新预算、新 prompt 的成绩混在同一张对照表里。

## 3. 核心实现边界

1. **候选与索引（B / C）**：B 复用向量 + BM25 + RRF / MMR 排序。C 把完整事件和综合原句组织成统一候选，保留父综合 ID、句号、时间范围和原始来源映射。注意：目前手头只有 69 条曾被检索到的综合文本，在 C/D 补齐完整的 91 条原生综合导出前，三组先统一用每题相同的原 5 条综合来保证公平。
2. **上下文依赖打包（C / D）**：D 拿到候选种子后，按 C 冻结的文本规则补全需要的前文（只拼原句，不改写事实、不自行换算日期）。C 和 E 先一起复核一次规则，修掉早期原型里发现的“日期句重复”“泛指过渡句带出多余前文”等问题，冻结后就不再看标准答案加特例。
3. **统一预算与渲染（F）**：事件和综合包共用一份 4,096 预算，不再硬塞 5 条完整综合；重合片段去重，同一综合内保持原句序并标省略号 `[...]`，整个依赖包放不下就直接跳过。给模型看短编号（`[E1]`、`[E2]`），长来源 ID 留在 trace 里。**计数和渲染全组统一调 F 的模块，各人不要自己写估算。**
4. **回答与评分（E / F）**：所有阶段二方案共用同一时期模型、同一份 prompt 和短答案格式，取消阶段一的 6 词长度软限制（列举题允许答全）。每次运行绑定 `run_id`、`variant`、实际请求与 `usage`，失败和弃答单独计数、保留在总分母里。

补充说明：把句子追溯回父综合不等于已经验证了原始对话蕴含，规则补齐前文也不是完整指代消解器；本版不训练模型，也不加在线 LLM 规划。

## 5. 实验设计与评价口径

阶段二正式回答的核心三组（同候选、同模型、同 prompt、同 4,096 预算）：

| 代号 | 方案说明 | 实验目的 |
| --- | --- | --- |
| **M** | 固定 5 条完整综合 + 事件混合检索/MMR | 简单强基线 |
| **N** | 事件与综合句联合排序，直接摘取完整句 | 检验“拆句 + 统一预算”本身带来的收益 |
| **A** | 与 N 完全相同的候选和排序，额外保留指代/时间前文 | 检验“上下文保护”有没有独立收益 |

说明：整段联合打包 **U** 已做过离线对比，如正式回答需要进一步区分粒度影响再补跑；阶段一的 S0/S2 留作历史记录，D 补齐 S1（去综合）的必要消融即可。

**两步走验证**：

1. **开发集（30 题）**：先跑通 M / N / A，调顺流程并冻结全部参数和规则；
2. **留出集（约 100 题）**：配置冻结后，在剩下的 7 个留出会话（`conv-49/44/47/50/43/26/30`）上验证泛化。A 用固定随机种子按类别与会话轮转抽样（目标四类各 25 题并覆盖 7 个会话，题数不够先定好补足规则）。记忆构建针对完整会话进行，绝不看答案调参。

**必报指标**：原始正确数 / 固定分母、分题型与分会话结果、两两逐题胜负、支持覆盖与丢失项、实际 API `usage`、各阶段（构建/检索/回答）成本，以及人工复核发现的分歧。

**结果怎么写**：如果最终发现上下文保护（A）相对普通逐句（N）没有额外准确率提升，就如实写“未观察到独立收益”；如果反而拖累准确率，就诚实推荐简单逐句版（N）并保留消融分析。扎实的复现、清晰的组合设计和诚实的对照分析本身就是合格的课设交付，不需要为了凑正结果硬堆机制。

**核心 API 调用估算**（不含留出集记忆构建）：

- 开发集 30 题（M / N / A）：**90 次回答 + 90 次裁判**；
- 留出集约 100 题（M / N / A）：**300 次回答 + 300 次裁判**；
- 额外的 S1、U 或 2,048 档回答按需要单独评估后再决定是否补跑。

开始批量付费调用前，先由 A / C 确认留出会话规模，F 按当日单价估算费用并登记预计 POST 次数；已跑通且配置/输入完全一致的结果直接复用，不重复花钱。
