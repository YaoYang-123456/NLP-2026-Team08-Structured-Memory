# 从规则学习到证据约束：MetaMem 个人试点阶段总报告

本研究包属于天津大学NLP课设第8队、专题4组2中杨垚负责的MetaMem个人试点，尚不是全组最终方案。真实完成了小规模符号规则学习、稳定性检查、证据补齐与自动检索对照、回答提示词成对实验。所有结论限定在反复使用的十道开发题；没有正式测试成绩、人工金标准或LightMem完整复现。

## 研究线索

最初的问题是“元记忆规则能否改善长历史回答”。本地7B自判先暴露了语义判分错误：格式修复能识别`No.`，不能修复目标时间或推荐理解。固定19条回答的新旧judge模板诊断未满足采用门槛，因此没有把失效judge直接用于扩展训练；之后改为明确标注的APP外部AI文件判分。

在v1政策下，固定20题每题两次真实生成，只有Apex旧目标题的混合正误组触发两次反思、一次提案、一次合并，学到一条自然语言规则：

> Prioritize recent memories, cross-validate facts, and understand context and chronology unless historical context is required.

这不是权重训练。规则来自训练题`9bbe84a2`；元数据列出20个ID并不表示所有题均贡献更新。原验证因uncertain没有满足完整覆盖，未正式选定B2。后续严格拒答v2澄清了“承认不足又猜”的口径，只离线重判旧回答，不伪造v2反思或重新训练。

第一阶段固定旧规则、把温度改为0.7后做十题三次采样。明信片旧优势未稳定重现，规则总体差距很小且有一次评审分歧。逐事实回接真实历史发现：晚餐和戒指确实漏检；明信片累计数量证据已在；海报/Sapiens跨事件和缺信息猜测；衣物与观鸟还受参考和时间口径限制。因此不能把全部失败叫作检索问题，也不能把得分等同于证据正确利用。

第二阶段用真实历史补齐两题做oracle诊断，再实现唯一自动候选：保持BM25排名、把user与other各限10块/6000字符，不回填空额。补证据让晚餐更能使用真正食材，但首饰仍有计数/日期错误；自动角色预算并未补回关键缺失，四组对照没有稳定收益。该检索候选只保留为可选实验，不替换默认基线。

第三阶段因此单独改变回答提示词，固定原BM25且两组均无规则。候选明确事件、时间、累计数量和证据不足处理，要求短引用依据；事实输入完全相同，原提示词重新生成基线，不拿历史分数直接相减。[第三阶段报告](metamem-stage3.md)给出新60条回答的正确性、依据质量、配对结果及一次独立复核。

## 已经实现与没有实现

已经实现真实LongMemEval数据来源/哈希、固定训练/开发清单、BM25事实输入、B0/B1/B2接口、多次回答、严格混合组筛选、反思/提案/合并、文件式外部AI判分、逐次保存和预算/清理、独立复核及可追溯统计。可讲解的核心是：自然语言元记忆影响事实利用，规则学习不修改模型参数；诊断实验分离检索与回答两个环节。

没有实现论文的LightMem压缩/主题聚合/长期维护、MiniLM检索、原论文大模型及judge、原规模五折。缩小实现不是失败，但必须明说。第三阶段提示词是人工设计的工程候选，不是新学出的元记忆。原文逐项页码见[方法对应](metamem-stage2-method.md)及[课程差距](metamem-course-readiness.md)。

## 可靠性与归因边界

- 检索遗漏与证据利用错误均有可核验案例，当前证据不足以量化全局哪一种占主导；两题oracle不代表全体。
- 参考正确、推理正确、证据支持是不同对象。猜中参考、把一般建议说成用户经历、引用真实ID却不支持结论，都会被单独保留。
- 角色预算改变了文本总量和组织，不是纯角色权重的唯一因果隔离；新提示词改变的是一个完整提示词包，不能从结果单独归因某一句指令。
- 衣物参考3的对象口径、观鸟历史晚于问题的as-of异常仍未解决。保留原标准主表，异常另列，不私改参考或删题。
- AI主评和独立AI复核均不是人工金标准；部署精确版本未知，隐藏条件也不等于严格盲评。一次复核后不一致保留uncertain。
