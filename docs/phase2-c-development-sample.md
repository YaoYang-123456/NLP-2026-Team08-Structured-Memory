# 阶段二 C 开发首样

[任务 #72](https://github.com/YaoYang-123456/NLP-2026-Team08-Structured-Memory/issues/72) · 2026-11-23 · 负责人 `oioioi-521`

首样使用 B 已联调的 `conv-48/86`，沿用第一阶段 S2 实际传给问答入口的 60 条事件和 5 条综合。5 条综合切分为 60 个带位置的原句，共 120 个候选单元。通过 C 开发交接清单核对该会话的 30 份输入文件，索引里的 171 个不同消息 ID 均能定位到原输入中的会话、消息位置和说话人。

## 接入

读取 [首样 JSON](../reports/artifacts/phase2-c-development-sample-20261123.json)。B/D 可以直接读取 `units` 枚举这批候选。原事件保留 S2 展示文本、时间和来源 ID。综合句保存父综合 ID、从 1 开始的句位，以及父综合完整文本中的字符区间。区间以 Unicode 字符计数，从 0 开始，右端点排除。

`parents` 保存原 S2 综合全文、时间范围和父级来源。句子级 `source_ids` 指向父综合，`source_scope=parent_synthesis` 表明这些来源需要按父级追溯。父综合的消息和事件引用是归档记录中的关联，逐句语义支持仍需复核。`available_event_ids` 标出同一首样里能直接查到的事件，所有其他父级来源 ID 仍保存在 `source_ids`。F 可以用父 ID、句位和时间范围渲染或重建片段。`source_messages` 提供原输入文件和 1 起始的消息位置，原始对话内容留在本地交接目录。

`dependencies` 单独保存已抽查原句的依赖。键对应候选单元 ID，值为需一起保留的原句 ID。空列表表示此样例的复核建议是暂不加边，缺少键表示该句尚未列入本次案例复核。

## 复跑

在仓库根目录运行，传入第一阶段 C 已验收的 `complete-handoff` 解包目录。

```powershell
python scripts/build_phase2_c_sample.py `
  --event-handoff path/to/complete-handoff `
  --out reports/artifacts/phase2-c-development-sample-20261123.json
```

脚本使用 Python 标准库。它核对 S2 归档和 conv-48 会话输入的 SHA-256，生成固定顺序的索引。输出来自归档中的证据文本及来源字段，题干、预测、评分类别和标签均未写入。新增模型请求为 0。
