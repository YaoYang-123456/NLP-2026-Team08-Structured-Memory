# MetaMem个人试点：十分钟讲稿与两分钟进度汇报

本讲稿供组内理解与后续录制使用；尚未录制视频，也不是全组最终汇报。讲述者可说“本试点”，不要把个人实现概括为六人已共同完成。图表、数字和原始定位见[统一总报告](metamem-integrated-report.md)与各阶段研究包。

## 十分钟讲稿

### 0:00–1:10　问题不是“记得更多”这么简单

这次个人课设读的是MetaMem。它研究一个容易被忽略的问题：检索到事实，并不代表模型能正确使用事实。例如历史里同时出现“原来17张”“又增加8张”“现在25张”，模型可能重复相加；也可能把一段相关经历误当成问题真正问的事件。

MetaMem把两类记忆分开：事实记忆M是“发生过什么”，元记忆E是“怎样使用已有记忆”。论文第3页的式1到式3说明，规则通过提示词进入回答，并不是继续训练模型权重。第4页Figure2、第5页式8到式10把流程展开成采样、判分、反思、提出编辑、解决冲突再更新规则。

我们这里实现的是缩小的BM25 RAG加自然语言规则试点。没有实现论文的LightMem压缩、主题聚合和长期维护，也没有使用论文的大模型或五折协议。这一点必须先讲清楚。

### 1:10–2:20　先把实验链条真正跑起来

本机使用Qwen2.5-7B四位量化模型，服务上下文8192。固定20条训练、10道开发题，回答不能看到参考答案。评分通过APP外部AI文件接口，身份、输入哈希和依据都有记录；它不是人工金标准，也不是后台付费API。

20条训练每题采两次、四批、只在同题有效答案有对有错时学习。实际只有一个题组触发了两次反思、一次提案和一次合并，学到一条关于近期信息、交叉核对与历史语境的规则。它确实来自训练流程，但不是每个批次都有有效更新。最初验证还有uncertain，按完整覆盖要求，没有选出正式候选。

后来把“拒答后仍猜所问事实”的评分政策明确为项目自己的严格拒答v2；这是评分定义变化，不是论文原标准，也没有因此重新训练规则。旧标签和选择记录都保留。

### 2:20–3:35　阶段一：一题优势能否重现

最初小表看起来学习规则多答对一道，但我们没有直接宣布有效。在同样10道开发题上各重复三次，温度统一为0.7，新生成无规则和有规则回答。

保守复核后，无规则17对、13错；有规则18对、11错、1不确定。这里是10道题重复三次，不是30道独立题。原来的明信片优势没有稳定重现，甚至有一轮只有无规则答对。一个Sapiens回答对条件假设与实际答案的界限存在争议，我们保留uncertain，而不是继续判到一致。

所以第一阶段的结论是：流程能学习和应用规则，但还没有证据证明这条规则稳定改善表现。负结果推动我们检查：问题究竟出在没找着事实，还是找着了不会用？

### 3:35–5:10　阶段二：把缺失和利用拆开看

先选晚餐和首饰两题，用原始历史补入已审计的必要证据，原事实和补齐事实各重复三次。这是参考辅助的oracle诊断，不能叫自动检索提升。

晚餐中，原事实没有真正召回香草和番茄来源；补齐后必要食材使用由0/3变为3/3，但仍有把一般食材说成用户自种经历的风险。首饰更有启发：补齐戒指后，模型仍可能漏掉它或把28天前误判为两个月之外；唯一答出数字3的一次，是把一对耳环算成两件再加项链，没有用戒指。数字碰巧匹配参考，与推理依据正确不是同一件事。

接着实现一个可自动部署的最小候选：BM25分数不改，只把user与其他角色各自限制在10块、6000字符。选择依据来自20条训练题的离线审计，不根据开发生成分数调参，也不删除全部assistant内容。

四组同轮对照结果为：原检索无规则16对，有规则17对；角色预算无规则15对，有规则17对，各30条观察。新候选没有补回已知关键事实，收益也不稳定。因此不替换BM25默认，只保留可选代码和失败解释。

### 5:10–7:10　阶段三：约束回答怎样使用现有证据

既然补齐事实也不保证正确使用，我们只改变回答提示词，保留原BM25、相同事实、模型、生成参数和无规则设置。候选要求区分对象、事件和参照时间，给简短可核验依据并引用实际fact ID；计数区分累计、增量与件数；信息不足时指出缺什么，不继续猜；推荐内容区分用户明确经历与一般建议。

候选是在生成前冻结的，没有写开发题答案或针对题号的分支。先运行四题24条，检查保存和输入预算后继续其余六题36条，无论前四题表现怎样都不改候选。主对照新生成基线，不把上一阶段成绩直接拿来相减。

正确性继续沿用v2，依据支持、时间计数、引用是否支持以及拒答是否合适另作质量维度。真实ID不等于支持结论；即使正确性判Yes，错误理由也必须留下。影响主要结论的分歧只独立复核一次，无法解决就保留uncertain。

结果没有给出全面提升：原提示词三轮分别6、5、6对，候选三轮都是5对，总共17对对15对，覆盖都完整。两组同对14次、同错12次；仅候选对的一次是第二轮明信片，仅原提示词对的三次全部来自晚餐。明信片由两次对变成三次对，但晚餐由三次对变成全部错，两个不可答题仍然全部失败。

质量变化比总分更细：有依据支持从9条到13条，明确不支持从19条减到12条，但不确定也从2条升到5条。时间计数依据有效从3条到7条，仍有8条无效。候选虽然28条回答的引用ID存在，只有12条的引用确实支持断言，15条不支持，3条不确定。引用格式整齐，并不等于证据使用正确。

输出token从9712降到3116，约减少68%，说明更简短；但它没有解决跨事件混淆和不足时猜测，而且损害了推荐题。独立复核保留23个质量维度分歧，不是23个新答案。没有明确发现新增过度拒答，衣物题两组仍各有3条拒答适当性不确定，不能证明没有风险。因此保留为可选研究候选和负结果，不切换默认。

### 7:10–8:30　怎么理解这些实验

三个阶段是一个研究链条：先检验规则是否稳定，再拆分检索缺失和证据利用，最后对后者做单变量干预。各阶段的不同温度、评分版本和干预不能混成一个总体正确率。所有开发题已经参与方法设计，因此即使第三阶段改善，也只能保留为候选、值得独立评估，不能称泛化提升已证明。

还有两种评测边界一直没有消失。衣物题参考3的计数口径不明确；观鸟题给定历史有晚于问题时间的内容，原评分又允许一单位容差。我们继续保留它们在主表里，同时单列解释，不改参考、不删题来提高分数。

更重要的是，AI判分与人类确认不同。隐藏了条件名称也不代表严格盲评，回答的引用风格本身可能泄露条件。我们保留原始判分、复核及保守派生结果，不把一致率说成judge准确率。

### 8:30–10:00　交付与下一步

现在已经形成可运行的本地生成、文件判分、规则学习、对照实验和成本记录，也有真实历史来源审计、失败恢复、图表和讲稿。没有模型权重更新，没有LightMem全复现，没有正式测试成绩；Markdown研究包也还不是老师要求的最终PPT、Word和视频。

后续最值得做的一件事，是集中人工核对代表性证据和评分口径，再决定冻结哪个方案进入独立评估，而不是再加第四个开发提示词追分。尤其要核对“数字正确而理由错误”、推荐题引用要求与原评分口径的关系，以及衣物和观鸟异常。之后固定代码、模型、检索、提示词、规则、评分政策、复核与缺失处理，再确认是否打开独立测试；不能用AI意见冒充人工修订。

最终小组还需要决定如何把这份个人试点和其他五篇论文整合，制作系统PPT与Word并录制视频，提交方式以老师后续通知为准。我们的阶段成果是把“为什么有效或为什么没用”变成可追溯证据，而不是保证某张表一定涨分。

## 两分钟进度汇报

我负责MetaMem个人试点，已经把本地Qwen7B、BM25事实检索、外部AI文件判分和小规模规则学习跑通。20道训练题实际只触发一个混合正误题组，学到一条规则；不是模型权重训练，也不是LightMem完整复现。

第一阶段用10道开发题各重复三次检查稳定性：无规则17对，有规则18对和1条不确定，原先明信片优势没有稳定重现。因此我们没有宣布规则有效。

第二阶段把检索缺失和证据利用分开。晚餐补齐真实食材后，必要证据使用由0/3到3/3；但首饰补齐后仍有日期误读和碰巧答对数字。自动角色预算检索没有补回关键证据，四组16、17、15、17对，不值得替换原BM25。

第三阶段固定事实与无规则设置，只比较原提示词和一个通用证据约束提示词，每组30条新回答，同时看正确性与依据质量。结果是原提示词17对、候选15对：明信片改善一次，晚餐三次都退步。依据支持由9条到13条，输出约少68%，但两个不可答题仍全部失败；引用真实ID也常不支持结论。因此只保留可选候选，不切换默认。这10题已参与开发，结果不代表独立泛化。

现在有代码、冻结配置、来源审计、逐题统计、图表和复现说明。下一步先集中人工核对证据与评分口径，再决定冻结方案和独立测试；不再加第四方案，本轮没读测试题。组内还需确认路线整合，补齐最终PPT、Word和视频。所有判分目前是AI评审，人工验收留空。
