# 第二阶段：检索候选依据与论文方法对应

本文件记录**生成新回答前**基于训练输入与已有证据审计作出的工程选择。它不是开发集得分驱动的调参记录，也不把训练检索统计称为证据召回率。候选只考虑两种，最终只实现角色分组预算；同会话邻域扩展没有实现。第二阶段实际分数、生成配置哈希及冻结时点以[主报告](metamem-stage2.md)及其运行产物为准。

## 训练集为何支持一个最小候选

只读取既有 `data/pilot/train.inputs.json` 的20题，无模型调用，不读训练参考，不读测试题和答案。基线是180词消息块的BM25排序，k1=1.5、b=0.75，最多20块、正文合计最多12,000字符；日期和角色包含在正文内。数字是消息文本的Python字符数，不是token数或显存。

|原检索工程指标|20题合计|
|---|---:|
|已选消息块|388|
|user块|226|
|assistant块|162|
|user正文字符|70,126（32.46%）|
|assistant正文字符|145,886（67.54%）|
|assistant块数过半的题|6/20|
|达到12,000字符上限的题|6/20|

角色与信息价值不能等同：

- 训练题 `gpt4_0b2f1d21` 问咖啡机购买与搅拌机故障的先后。首位 `answer_c4e5d969_2:9:0` 是assistant给出的咖啡机甜点建议；其较长的建议文本占据预算，但不直接给出所问事件时间。这是可核验的词面相关与证据作用不一致案例，不是对所有assistant消息的语义标注。
- 训练题 `6222b6eb` 问此前提过的SIAC_GEE算法。首位 `answer_sharegpt_H9PiM5G_0:13:0` 是assistant，直接写出6S对应SIAC_GEE。该题问的是既有会话说了什么，不能为了减少噪声把assistant一律删去；也不能把这段历史陈述当成本轮独立核实的软件事实。
- 训练题 `87f22b4a` 问卖鸡蛋所得，排名中同时出现卖夹克的120美元与assistant养鸡建议；用户的每打3美元和40打自述也在其中。角色预算无法自动解决跨实体混淆，不能预先宣称模型会正确使用被保留的事实。

上述统计和案例在实现、查看本轮10题生成分数前形成。没有完整相关性标注，所以不报告precision、recall或“召回提升百分比”。

## 两个候选与选择

|候选|改变的机制|选择依据与局限|本轮状态|
|---|---|---|---|
|角色分组预算BM25|user与assistant/system各最多10块、6,000字符；组内仍是同一BM25分数排序，最后恢复全局BM25顺序|训练中assistant块较长、占67.54%字符；约束预算容易实现与审查。仍保留assistant，可能挤掉有用长回答，也可能少用总预算|选用、实现；不依据本轮开发生成成绩改参|
|同会话邻域扩展|为高分片段带入邻近turn|能保留局部因果关系，但一轮对话的邻近不保证关键事实相邻，可能扩入更多长建议；需要另定邻域与种子预算|未实现、未试跑|

选定方案只改变**角色分组的选取预算**。词法分词、BM25评分、180词分块、日期呈现及回答提示词不变；不加时间过滤，不做会话邻域，不按题号、参考答案、正确会话或开发得分挑事实。assistant和system合为other组；某组未用满的额度不转给另一组，保持实现与解释简单。总上限仍为20块、12,000字符，但实际长度可能更短，因此结果可能同时反映保留内容变化与干扰文本减少，不能称为严格等长干预。每条事实保留来源ID，截断仅保留原始文本前缀；同一检索条件下有/无规则共享完全相同事实哈希。

这是一项可在仅有问题与历史时运行的工程替代检索方法，**不是MetaMem论文提出的角色配额算法**。它也不等于oracle补证：oracle由已知问题和审计定位证据，只测覆盖的可能作用，不作为自动方法。

## 冻结后的训练集工程检查

对已生成的 `output/stage2-retrieval/train.improved.inputs.json`、`metrics.json` 与 `facts-diff.json` 做只读检查，未运行训练模型、未使用训练参考或开发生成得分。

|20题工程量|原BM25|角色预算|
|---|---:|---:|
|总正文字符|216,012|183,573|
|user正文字符|70,126|63,573|
|other正文字符|145,886|120,000|
|事实块数|388|340|

20题事实哈希全部改变；合计新增25个fact ID、移除73个，实际正文少32,439字符（约15.0%）。**用户字符总量也减少**，不是单向“增加user信息”：10块上限会删去原来超过10块的user事实。训练集中user字符增加6题、减少14题；other组每题都用到6,000字符上限。该结果说明角色约束确实生效，不证明证据质量改善。

可核验的机制案例：

- 咖啡机/搅拌机题 `gpt4_0b2f1d21`：12,000→8,663字符，user 1,756→2,663；替换5个块。关键user自述 `answer_c4e5d969_1:0:0`（咖啡机约三周前购买）与 `answer_c4e5d969_2:0:0`（上月搅拌机送修、修了两周）均保留于候选。这是内容证据检查，未据此报告模型正确率或召回率。
- SIAC_GEE题 `6222b6eb`：12,000→8,628字符，新增1/移除4个块；仍保留直接回答来源assistant块 `answer_sharegpt_H9PiM5G_0:13:0`。说明该候选不是user-only过滤器。
- 鸡蛋题 `87f22b4a`：12,000→9,190字符，user 2,372→3,190；新增2/移除3个块。角色预算仍不能判定哪些价格与鸡蛋属于同一事件，后续模型表现应单独观察。

完整逐题变化与被截短的同ID正文保存在facts-diff，不能仅凭新增/移除ID判断内容完全未变。基线20题从去标注原历史重新检索逐项相等，候选保留现有评分与排序；基本工程可用后冻结，分数不好也不重新调额。

## 结果解释的约束

主实验比较同轮A原检索/空规则、B原检索/旧规则、C角色预算/空规则、D角色预算/旧规则。C−A与D−B反映该固定检索替代下的观察；B−A与D−C反映规则在两种证据条件下的观察。每个条件三次仍只有十道开发题，不是三十道独立样本。既有参考歧义、时间异常和AI判分不确定性继续保留，不为了满足覆盖强行给标签。

oracle两题不足以确定整体瓶颈。晚餐原正确性已达到上限，补证的价值还需看“实际用到关键证据”和“无依据归因”这两项独立质量指标；不能悄悄替换原正确性标准。完整训练审计、事实变化及实际生成成绩由本阶段主产物补充，本文不预写提升结论。
