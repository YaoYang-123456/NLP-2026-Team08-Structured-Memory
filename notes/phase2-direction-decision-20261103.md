# 阶段二方向决定：预算约束下的多粒度证据打包

日期：2026-11-03。阶段二的主线定为：**在已复现的 StructMem 上，实现预算约束的多粒度证据打包，并在摘取综合句时保留必要的人物指代与时间前文。** 定位是课程级组合改进，集中精力把这一条线做实，不再同时铺开失真检测、来源多样性、知识图谱或元记忆训练。

建议课设题目：**面向长对话问答的结构化记忆复现与改进——预算约束下的多粒度证据打包**。方法简称直接叫“上下文保留打包”即可，不必生造花哨的系统名。

## 1. 为什么选这个方向

阶段一已经跑通了 StructMem 的事件记忆和跨事件综合，但回答阶段对两层记忆的用法很粗放：直接把 `top-60 事件 + top-5 完整综合` 拼在一起。统一限制到 4,096 token 后我们发现，光 5 条完整综合就平均占了一半额度——综合里确实有跨事件脉络，但也夹杂了不少和当前问题无关的句子，反倒把关键事件挤掉了。

之前我们试过“互补选择（C-v1）”，只调事件排序而固定 5 条综合，结果没超过普通 MMR。换个思路：**打破固定 5 条整段综合的做法，把综合拆成句子和事件一起按预算竞争**，检索时按句找准，展示时按需返回“完整事件”或“选中综合句 + 必要前文”。既省下预算给事件细节，又不至于把句子截得没头没尾。

在 30 道开发题上做的离线试点支持了这个判断（详见[多粒度试点报告](../reports/phase2-anchor-pilot-20261103.md)）：同样 4,096 token 预算下，旧的固定 5 条综合 + MMR 覆盖 **48/51** 项支持证据，整段联合打包达到 **49/51**，普通逐句和上下文保留打包都达到 **50/51**，且原答对的 19 题支持全部保住。不过离线覆盖只是第一步，上下文保留到底能不能独立提高回答准确率，需要后续正式回答实验来检验。

## 2. 文献关系与创新边界

| 已有工作 | 借鉴点 | 本项目的位置与边界 |
| --- | --- | --- |
| [StructMem](https://aclanthology.org/2026.acl-short.12/) | 事实/关系事件绑定与跨事件综合（附录 A.3 默认取 60 条事件 + 5 条综合） | 沿用其记忆构建，改进回答前如何从两层记忆里挑证据和分配预算（原文已有事件重建，不声称我们首次保留事件结构） |
| [Semantic XPath](https://aclanthology.org/2026.acl-demo.28/) | 按层级结构选合适范围，把相关子树交给下游 | 借鉴“按结构范围取上下文”的思想，用父综合、句位和前文依赖替代完整的 XPath 查询生成 |
| [Hindsight](https://aclanthology.org/2026.acl-demo.27/) | 多路检索、RRF、显式 token 预算、区分发生时间与记录时间 | 混合召回和 token 预算作为已有工程基础使用，不包装成创新；不部署其整套图/数据库服务 |
| [RECOMP](https://arxiv.org/abs/2310.04408) | 抽取式相关句选择与摘要压缩 | 把“普通逐句摘取（N）”设为强对照；我们不训练压缩器，也不额外生成摘要 |
| [LongLLMLingua](https://aclanthology.org/2024.acl-long.91/) | 面向问题的上下文压缩与预算控制 | “压缩上下文”并非新概念；本项目限定为完整事件/句子及前文依赖约束，不做 token 级删词 |
| [LongMemEval](https://arxiv.org/abs/2410.10813) | 会话分解、粒度选择、事实增强索引、时间范围检索 | 粒度和时间问题已有系统研究；本项目的价值在于迁移到 StructMem 并做可控对照 |

另外，我们在文献调研时查到一篇邻近工作 [PEC-HOP / MCE-Compass](https://aclanthology.org/2026.emnlp-main.849/)，其公开摘要提到了非参数、保留指针的证据压缩（本轮仅访问到摘要，全文页面暂未打开，后续由 D 补读核对）。因此我们更明确地把项目定位为课程级组合改进，不声称“首次提出可追溯/保留指针的压缩”。

**可直接用于答辩或向老师汇报的表述**：

> 在复现 StructMem 的基础上，结合结构化范围检索与抽取式上下文压缩的思想，设计了预算约束下的多粒度证据打包方法。该方法将检索粒度与展示粒度分开，在事件和综合片段之间统一分配上下文额度，并对人物指代、相对时间等上下文依赖做整包保留，系统评估其对证据完整性、问答效果和推理成本的影响。

汇报时要把“已有组件（MMR、提示词统一、短编号）”和“核心组合设计（StructMem 双层记忆 + 统一预算 + 上下文依赖成组保留）”分清，避免把普通工程整理包装成算法创新。

## 3. 方法范围

1. 复用现有事件库、综合库和本地嵌入模型，用向量 + BM25 混合检索生成候选。
2. 检索单元为“完整事件”和“综合里的单个完整句”（只拆索引，不改写综合原文）。
3. 用问题相关性 + MMR 挑种子；选到综合句时，按规则检查指代词和相对时间，把需要的前文组成一个依赖包，同时保留父综合 ID、句号和时间范围。
4. 事件和综合包放进同一个 4,096 预算里一起选，重合片段只计一次；整个包放不下就跳过，绝不截断半句话或丢掉否定词/前文。
5. 完整保留原文片段、省略标记 `[...]` 和请求记录，方便复查（注：能追回综合原句不代表原始对话级蕴含已验证，仍需 C/E 核对）。

**明确不做**：不训练模型，不加在线 LLM 查询规划，不建知识图谱，不做全库失真分类，不把题型、标准答案或参考 evidence 喂给选择器。前文保留采用透明、可检查的启发式规则，不冒充完整指代消解器。

早期研究原型里，抽查发现规则还偏保守：有的日期句其实已经被时间范围涵盖，有的过渡句（如 `"This exchange..."`）会顺带拖出无关前文。正式实现前，由 C 和 E 按文本逻辑统一复核并冻结一版规则，但不围绕具体题目的标准答案写特例。

## 4. 怎样证明改进有价值

正式实验对比核心三组：**固定综合 + MMR（M）**、**普通逐句打包（N）**、**上下文保留打包（A）**。N 和 A 的候选池、向量、排序、prompt 和预算完全一致，唯一差异就是是否补齐前文依赖。整段联合打包（U）已做离线对照，需要进一步定位粒度影响时再补回答。

- **预算档位**：以 4,096 为主；2,048 档在试点里丢了 1 题原已答对题的支持，只作为质量/成本权衡点报告。
- **评价维度**：同时报告支持覆盖、真实回答正确率、完整/部分证据丢失、真实 API `usage`、调用次数和本地检索耗时。
- **区分结构指标与语义效果**：规则判定的“缺前文句数减少”只是结构检查，不等于模型真的多答对了题。目前 N 和 A 离线覆盖相同，A 有没有独立价值要看最终人工复核和实际回答结果；如果没差异，就诚实报告。
- **避免过拟合开发集**：30 道开发题已经用来做过几轮探索，配置冻结后统一在 7 个留出会话（约 100 题）上做泛化检验，看完留出结果不再回头调参。

哪怕最终上下文保护没有带来额外准确率提升，我们依然有完整的 StructMem 复现、可运行的多粒度打包方案、清晰的预算权衡与消融结论——按实测结果给出准确结论即可，不强行许诺全指标上涨。
