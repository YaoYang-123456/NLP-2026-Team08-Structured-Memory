# 下一阶段方向决定：预算约束下的多粒度记忆与上下文保留

日期：2026-11-03。**主方向确定为：在 StructMem 上实现预算约束的多粒度证据打包，保留被选综合片段所需的人物指代与时间上下文。** 定位为课程级的组合改进，不声称提出新的通用检索理论。后续围绕这个方向实现和验证，不再同时推进失真检测、来源多样性、知识图谱和元记忆训练等多条主线。

建议题目：**面向长对话问答的结构化记忆复现与改进——预算约束下的多粒度证据打包**。方法简称可用“上下文保留打包”，不需要另造一个夸张的系统名称。

## 1. 为什么选这个方向

现有工程已经能构建事件和跨事件综合，但回答端对两种粒度的使用比较固定：事件 top-60 与综合 top-5 直接拼接。上轮统一到 4,096 代理 token 后，五条综合平均占掉约一半额度。综合有用，却不需要每次把整段无关叙述都交给回答模型。

前一轮互补选择只改变事件排序，没有超过 MMR。新的切口是**改变检索单元到实际上下文的映射及事件/综合的预算分配**：可以按句找相关内容，最终给模型的单元则是“完整事件”或“所选句＋必要上下文”。这样保留综合的联系信息，也让事件细节有机会进入预算。

本轮额外完成 30 题、两档预算、三种打包方式的离线检查。4,096 档，旧固定综合＋MMR 为 48/51 项，新整段联合选择为 49/51，普通逐句摘取与上下文保留方案均为 50/51；原答对 19 题的支持全部保留。详见[试点报告](../reports/phase2-anchor-pilot-20261103.md)。这支持继续做粒度/预算改进，但没有证明上下文保留机制独立提高答案准确率。

## 2. 文献关系与创新边界

| 原有工作 | 可借鉴内容 | 本项目的位置 |
| --- | --- | --- |
| [StructMem](https://aclanthology.org/2026.acl-short.12/) | 事实/关系事件绑定、跨事件综合；附录 A.3 为问答检索 60 条事件和 5 条综合 | 保留已有构建；修改回答前如何使用两层记忆。原文正文已有事件重建，不能声称我们首次保留事件结构 |
| [Semantic XPath](https://aclanthology.org/2026.acl-demo.28/) | 根据层级结构选择合适范围，把相关子树交给下游 | 借鉴结构范围约束；用父综合、句子位置和上下文依赖代替完整 XPath 查询生成，不宣称完整复现它 |
| [Hindsight](https://aclanthology.org/2026.acl-demo.27/) | 多通道检索、RRF、明确 token 预算，区分发生时间与记录时间 | 混合召回和预算是已有基础，不作为创新；本阶段不部署其数据库和完整图系统 |
| [RECOMP](https://arxiv.org/abs/2310.04408) | 从检索材料中抽取相关句，或生成压缩摘要 | 普通逐句选择作为强对照；我们的实现不训练压缩器，不额外生成摘要 |
| [LongLLMLingua](https://aclanthology.org/2024.acl-long.91/) | 面向问题的上下文压缩与预算处理 | “压缩上下文”并不新；本项目限定为完整句/事件以及上下文依赖约束，不做 token 级删除 |
| [LongMemEval](https://arxiv.org/abs/2410.10813) | 会话分解、粒度选择、事实增强索引、时间搜索范围 | 粒度和时间处理已有系统研究；本项目的贡献在具体迁移、对照和适配，而非重新发现这些原则 |

另有 [PEC-HOP / MCE-Compass](https://aclanthology.org/2026.emnlp-main.849/) 的公开摘要提出非参数、保留指针的证据压缩，和这里的“可追溯压缩”存在邻近性。本轮检索到其官方摘要，全文页面打开失败，未完成算法级逐项对照；因此尤其不能宣称“首次保留指针/上下文”。原文及作者实现后续由 D 补核，但不阻止按课程级融合定位实施。

**可对老师使用的表述：**

> 在复现 StructMem 的基础上，结合结构化范围检索与抽取式上下文压缩，设计预算约束的多粒度证据打包方法。方法将检索粒度与展示粒度分开，在事件和综合片段之间统一分配上下文额度，并对人物指代、相对时间等上下文依赖进行成组保留，研究其对证据完整性、问答效果和成本的影响。

这里的小改进落在“StructMem 双层记忆＋统一额度＋上下文依赖成组保留”的具体设计、实现和验证。融合方法可以成为课设贡献，但现有组件、工程优化和新的组合设计应分清。不能把只做 MMR、删长 ID、换提示词分别包装成三项算法创新。

## 3. 方法范围

1. 复用现有事件库、综合库与固定嵌入；用混合检索准备候选。
2. 以完整事件和综合中的完整句作为检索单元。同一父综合只拆分索引，不改写正文。
3. 根据问题相关性和普通 MMR 选种子；对综合句检查指代和时间线索，将需要的前文组成一个包。保留父综合 ID、原句位置和时间范围。
4. 将事件和综合包放在同一额度下选择；包内重合内容只计一次。放不下就跳过，不能为了塞进预算删掉否定、半句话或依赖句。
5. 原始片段与实际请求均可重建；省略处明确标记。追溯到综合原句不等于已证明该句被每条原始对话蕴含，原始消息级支持仍需 C/E 核对。

第一版不训练模型，不加在线 LLM 查询规划，不重建知识图谱，不做全库失真分类，也不把类别标签、参考答案或 reference evidence 输入选择器。上下文保留是可检查的启发式，不是完整指代消解器。

已实现的研究原型使用前文指代线索闭包与最近显式日期句，完成一次固定配置试点。抽查也发现一些日期句与保留的时间范围重复、一些概括性过渡句会带入不必要前文。C/D 在正式实现前应依据文本依赖核对这些规则，形成一次冻结版本；不能按某题答案手工挑关联句。现有原型结果、配置和缺陷照存，不覆盖成修正后的成绩。

## 4. 怎么证明这点改进有意义

正式实验核心三组为：固定综合＋MMR、普通逐句打包、上下文保留打包。后两组的候选、向量、排序、指令、预算完全一致，只有上下文扩展不同。整段联合打包已作为本轮额外离线对照，必要时补回答。

- 默认 4,096 代理 token；2,048 只作成本/质量权衡点。本轮小预算发生已答对题支持丢失，不能把“预算减半”写成无损优化。
- 同时报告逐题支持覆盖、实际答案正确性、完整/部分证据损失、真实 usage、调用次数和本地检索开销。
- “规则要求的上下文缺口减少”是结构性检查，不等于消歧成功，更不能等同于修复了同样数量的答案。
- 普通逐句方案与上下文保留方案目前覆盖相同，独立价值必须通过成员复核和实际回答再判断；若最终也相同，诚实报告保护机制没有额外准确率增益，不夸大消融。
- 当前 30 题已用于多轮探索，不用于显著性或泛化结论。主配置冻结后，在原 7 个留出会话上评估；看留出结果后不再挑参数覆盖首轮成绩。

即使上下文保护不带来额外答对题，项目仍有明确的复现主线、可运行的组合方法、预算对照与消融。最终贡献按实测结果写成“相同预算提升支持覆盖”或“在一定损失下节省上下文”等准确结论，不预先许诺全指标提升。
